# 技术说明：Homeworld Remastered 的纹理预算闸门

> 本文记录 `se9ccn_texture_budget` 的依据：字节、地址、实测数据、以及为什么用"改立即数"而不是别的方案。
> 证据来自对 `HomeworldRM.exe`（2.303 / build 3409635）的反汇编与运行期观测。

## 1. 闸门在哪儿

纹理上传的唯一入口：`FUN_007B4C80`（RVA `0x3B4C80`，`__thiscall`）。反编译关键片段：

```c
uVar3 = (bpp * (fmt + 3) * w * h) / 6;      // 本张纹理的估算字节数
*(uint*)(tex + 0x18) = uVar3;               // 单张纹理记账
delta = uVar3 - old;                        // 旧值
DAT_009aed28 += delta;                      // 64 位全局计数器（低 dword @0x9AED28，高 @0x9AED2C）
if (DAT_009aed2c >= 0 && (DAT_009aed2c != 0 || 0x77770000 <= DAT_009aed28)) {
    return 0;                               // ← 超预算：纹理创建失败
}
... glTexImage2D ...
```

对应机器码（文件偏移 `0x3B40F7` = RVA `0x3B4CF7`）：

```
78 13                    js   short ok        ; 高 dword 为负 → 放行
7F 08                    jg   short fail      ; 高 dword 为正（总量 ≥ 4GiB）→ 失败
81 FF 00 00 77 77        cmp  edi, 077770000h ; ← 这里就是上限
72 09                    jb   short ok
                         ; fail: xor al,al; ret
```

- `edi` = 计数器低 32 位，`0x77770000` = **2,002,796,544 字节 ≈ 1.867 GiB**；
- 全镜像里这个立即数**只出现一次**（字节级扫描确认），所以补丁点唯一。

## 2. 为什么 4 个种族就吃满、8 个种族必炸

- 资产普查（`.big` 解包 + HOD 内嵌贴图描述符反算）：4 个可选种族的船贴图合计
  **1903.9 MB = 该预算的 99.2%**；
- 8 个不同种族的运行期实测（本工具的姊妹工程用注入探针记录）：纹理计数器峰值
  **2,004,963,872 字节（100.03% 预算）**，同时 `Unable to retrieve UI` 出现 2,422 条；
- 8 种族时若第一张失败的恰好是**必需** UI 贴图，`UIGraphic::parseLODTextures`
  （RVA `0x2B8FF5`）会直接 `-- FATAL EXIT --`，原文：
  `Unable to load texture (data:UI\Pings\Meshes\Circle.mtga)`。

## 3. 为什么改"比较立即数"而不是别的做法

| 方案 | 评价 |
|---|---|
| **改 imm32（本工具）** | 只动 4 字节，语义不变（仍是"已用字节 vs 上限"），可配置上限；签名校验后可安全拒绝不匹配版本 |
| 把 `JB` 改成 `JMP` | 1 字节，但会让高 32 位检查在总量 ≥4GiB 时仍失败，且完全禁用保护，不够透明 |
| Hook `FUN_007B4C80` 重写闸门 | 该函数是 `__thiscall` + 自定义栈清理，且位于热路径；替身 hook 的 ABI/返回值一旦有误会污染整个绘制流程，维护成本高 |
| 运行期"削计数器"（把 64 位计数器定期下调） | 可行但依赖后台线程与游戏主线程竞争，记账仍是 delta 平移；不如改常量干净，且对将来也更好解释 |
| 降低贴图分辨率 / 用 LAA（4GB 地址空间） | 前者是 mod 侧改动；后者只扩 VA，与这个纹理预算无关（实测 8 种族时进程 commit 仅约 1.1GB） |

## 4. 边界

- 计数器高 32 位为正时（总量 ≥ 4 GiB）仍会失败，因此 `budget_mb` 钳到 **4095**；
- 本工具**不修改磁盘文件**：补丁只存在于进程内存，游戏重启即恢复原状，再加载本 DLL 再打一次；
- 补丁依赖版本签名。游戏升级后若字节不匹配，DLL 只写日志、不改任何字节（失败安全）；
- 预算与显存是两件事：预算抬高后，若贴图总量超过显存，驱动会回退到系统内存，可能卡顿甚至崩溃；
  此时应降低 mod 的贴图分辨率，而不是继续加预算。

## 5. 验证方法

1. 启动游戏，看 `se9ccn_texture_budget.log` 是否有 `patched: ...`；
2. 开一局 8 个不同种族的 mod 对局（例如 8 人遭遇战、8 个不同种族）；
3. 观察任务栏/建造菜单图标是否还出现红黑方块；日志/游戏日志中不应再出现
   `Unable to retrieve UI (animated) texture` 或 `Unable to load texture`。
